# Genomic Testing Activity — dashboard

A React + TypeScript (Vite) dashboard showing regional variation in NHS genomic
testing across the 7 Genomic Laboratory Hubs (GLHs), benchmarked against the
England average. Built to match the Edge Health design reference.

## Run it

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # production bundle in dist/
```

## What's here

| Piece | Component | Notes |
|-------|-----------|-------|
| Top bar | `Header.tsx` | Source / updated / branding |
| KPI cards | `KpiRow.tsx` | National headline figures |
| Regional map | `RegionMap.tsx` | Real ONS ICB (April 2026) boundaries, ICB-level clicks, GLH shading |
| Metric toggle + ranking | `MapPanel.tsx`, `RankedList.tsx` | Tests / Per 100k / TAT / TAT % |
| Detail sidebar | `DetailPanel.tsx` | Selected hub stats |
| Performance-vs-national bars | `PerformanceBars.tsx` | Dashed line = England mean |
| 12-month trend | `TrendChart.tsx` | Recharts line chart |

All figures live in **`src/data/hubs.ts`** and are **placeholders**. The UI only
depends on the shapes in `src/types.ts` (`Hub[]` + `NationalSummary`), so the
whole component tree keeps working once real numbers arrive.

## Bringing it to life — what to add

### 1. Wire in real data (the main task)
`src/data/hubs.ts` currently exports static objects. Replace with a fetch. The
cleanest path:

- Add a small data layer, e.g. `src/data/useGenomicData.ts` with a
  `useQuery`-style hook (add `@tanstack/react-query`), pointing at your API /
  the NHS England Genomic Testing Activity feed.
- Map the response into the existing `Hub` / `NationalSummary` types — nothing
  downstream changes.
- Each hub needs a real 12-month `trend` array (currently generated by
  `makeTrend`); drop that helper once the feed supplies monthly points.

Fields to source per hub: total tests, tests per 100k, median TAT, % within TAT
standard, YoY growth, catchment population, lead provider.

### 2. The map — done
`RegionMap.tsx` renders the official **ONS ICB (April 2026) boundaries** (36
post-merger ICBs) grouped into the 7 GLHs, projected with the same linear
lng/lat → SVG approach as the fingertips-dashboard map (`src/hooks/useMap.ts`).
Clicking an ICB selects
it and its parent GLH. The ICB → GLH mapping lives in `src/data/icb-to-glh.json`
(from the `References.ICB_to_GLH` SQL table); regenerate the boundary layers
with `npm run build:map`. See `NEXT_STEPS.md` §1 for follow-ups (Dorset's GLH
assignment, GLH-straddling ICBs, April 2027 mergers).

### 3. Loading / empty / error states
Add skeletons for the KPI cards, map and sidebar while data fetches, plus an
error banner. Nothing handles a failed fetch yet.

### 4. Nice-to-haves
- **Time period selector** (the "Q3 2025/26" in the header is static).
- **Metric on the sidebar trend** — currently always tests-per-100k; let it
  follow the active map metric.
- **Deep-linking** the selected hub + metric to the URL (`?hub=ney&metric=tat`).
- **Accessibility pass** — the map regions are keyboard-focusable buttons; audit
  colour contrast on the lighter choropleth shades.
- **Tests** — Vitest + React Testing Library for the ranking sort and the
  vs-national delta logic in `PerformanceBars.tsx`.
- **Embedding** — if this goes in an iframe (per the Edge Health labs hub),
  check the `#root { max-width: 1400px }` and sticky sidebar behave in the host.

### 5. Data caveats to confirm before publishing
The placeholder catchment is shown in **millions** ("catchment 6.7m"); confirm
the real unit. Provider trusts in `hubs.ts` are best-guess leads — verify
against the official GLH list.
